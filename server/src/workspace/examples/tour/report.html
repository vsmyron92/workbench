Agents in the middle

A Claude Code session sits next to everything it touches. Here its changes are under review: Review Changes lists every file the session wrote against its version from before the session, with Revert per file or for all, while the project tree and the git log stay in view. Claude Code, Codex, Kimi Code, Gemini CLI and Aider are presets; any other CLI is a line in config.toml. GitLab and GitHub, Confluence and Jira sit on the right, and all of it is one program with the UI built in.

CI with a way out

GitLab pipelines and GitHub Actions runs show their jobs, logs and failed tests. Ask agent to fix on a failed job or test starts a session whose prompt already carries the output, so the agent starts from the failure instead of from a description of it.

Deliverables, not scrollback

When an answer needs more than terminal text, an agent hands it back as a Workspace card: a report, a gallery, a PDF, a 3D comparison. Reports are served sandboxed, so they cannot read Workbench's cookies, storage or API. This page is one of them.

Everything that runs

Run configurations come from your project files, environments get health checks and previews, and deploys always ask first.

In your pocket

Pair a phone, add Workbench to its home screen and turn on push. An agent that needs you sends a notification with Allow and Deny on it, and a failed pipeline opens with Retry and Ask agent at hand.

Before you open it up

Put TLS in front (tailscale serve, a reverse proxy or [server.tls]) and pair only devices you own. A signed-in device can type into terminals.
