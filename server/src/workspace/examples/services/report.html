Connect your services

Workbench example · a checklist, not a setup: this card connects nothing by itself

Connect only what your work needs

Everything below is optional. Workbench is useful with a git repository and one agent CLI; each service you add brings its own window and MCP tools for your agents. Tokens stay where you keep them: configuration names them by reference, and their values never reach the browser, a command line or a log.

Check your own setup

  1. Open Settings › Secrets: every reference, whether it resolves, and a fix for token files others can read.
  2. Open Settings › Integrations and fill in only the services you use.
  3. Try one read-only action per service: list merge requests, open a Confluence page, run select 1 in a console.
  4. Start an agent session and ask it to do the same through its tools, for example “list the open merge requests”.
  5. Keep writes for when you are watching: comments, retries and new merge requests all happen with your token.

Safe to share

.workbench.toml in the repository: run configurations and the names of secrets.

Machine only

~/.config/workbench/projects/<id>.toml (on Windows under %APPDATA%\workbench): hosts, deploys, secret references.

Never in a file you commit

A token's value. Use a file, an environment variable, a .env key, the keyring or a command.
